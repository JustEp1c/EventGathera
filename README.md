# EventGathera
Проектная работа, выполняемая в ходе прохождения курса "Продвинутая разработка на C# и .NET" от Яндекс.Практикум.

## Стек технологий

- .NET
- ASP.NET Core Web API
- Swagger

Перед запуском убедитесь, что установлены:

- .NET SDK 10
- IDE или редактор кода

## Инструкция для запуска проекта

1. Склонируйте репозиторий:

```bash
git clone https://github.com/JustEp1c/EventGathera.git
```
2. Перейдите в папку проекта:

```bash
cd EventGathera
```

3. Восстановите зависимости:

```bash
dotnet restore
```

4. Запустите приложение:

```bash
dotnet run --project .\src\EventGathera.Api\
```

После запуска в консоли будет отображён адрес приложения:

```bash
https://localhost:7153
http://localhost:5163
```

После запуска документация Swagger будет доступна в браузере по адресу:

```bash
https://localhost:7153/swagger
```

## Возможности

Приложение поддерживает базовые CRUD-операции:

- создание события
- получение списка событий
- получение события по идентификатору
- обновление события
- удаление события
- создание брони
- получение брони по идентификатору

### Фильтрация и пагинация событий

- **Фильтрация по названию** - поиск событий по частичному совпадению в названии (регистронезависимый)
- **Фильтрация по дате начала** - получение событий, начинающихся после указанной даты
- **Фильтрация по дате окончания** - получение событий, заканчивающихся до указанной даты
- **Комбинированная фильтрация** - одновременное применение нескольких фильтров
- **Пагинация** - разбивка результатов на страницы с настраиваемым размером

## Модели данных

### Event (Событие)

| Поле | Тип | Описание |
|------|-----|----------|
| Id | Guid | Уникальный идентификатор события |
| Title | string | Название события |
| Description | string | Описание события |
| StartAt | DateTime | Дата и время начала |
| EndAt | DateTime | Дата и время окончания |

### Booking (Бронь)

| Поле | Тип | Описание |
|------|-----|----------|
| Id | Guid | Уникальный идентификатор брони |
| EventId | Guid | ID события, на которое бронируют |
| Status | BookingStatus | Текущий статус брони |
| CreatedAt | DateTime | Дата и время создания брони |
| ProcessedAt | DateTime? | Дата и время обработки (для Confirmed/Rejected) |

### Статусы бронирования (BookingStatus)

| Статус | Значение | Описание |
|--------|----------|----------|
| Pending | 0 | Ожидает обработки (начальный статус) |
| Confirmed | 1 | Подтверждена (после успешной обработки) |
| Rejected | 2 | Отклонена (по различным причинам) |

## API Endpoints

### Бронирования (Bookings)

#### GET /bookings/{bookingId}

Получить бронь по ID.

**Пример запроса:**
```http
GET /bookings/987fcdeb-51a2-43d3-a456-426614174000
```
Пример ответа (200 OK):
```json
{
  "id": "987fcdeb-51a2-43d3-a456-426614174000",
  "eventId": "123e4567-e89b-12d3-a456-426614174000",
  "status": 1,
  "createdAt": "2026-04-14T10:30:00Z",
  "processedAt": "2026-04-14T10:30:05Z"
}
```

#### POST /events/{id}/book

Создать бронь на событие. Бронирование обрабатывается асинхронно в фоновом сервисе.


### Пример запроса

```http
POST /events/123e4567-e89b-12d3-a456-426614174000/book
```
Пример ответа (202 Accepted):
```json
{
  "id": "987fcdeb-51a2-43d3-a456-426614174000",
  "eventId": "123e4567-e89b-12d3-a456-426614174000",
  "status": 0
}
```

## Фоновая обработка бронирований
### Как это работает

1. Создание брони: При POST запросе на /events/{id}/book создается бронь со статусом Pending

2. Фоновая обработка: BookingProcessingService (BackgroundService) запускается автоматически при старте приложения и работает в фоне:

* Каждые 2 секунды проверяет наличие новых броней

* Находит все брони со статусом Pending

* Обрабатывает каждую бронь (имитация обработки занимает 5 секунд)

* После успешной обработки меняет статус на Confirmed и устанавливает ProcessedAt

3. Получение статуса: Клиент может GET запросом на /api/bookings/{id} проверить текущий статус брони

```text
Клиент → POST /events/{id}/book → Бронь создана (Pending)
                                      ↓
                            BackgroundService (каждые 2 сек)
                                      ↓
                            Обработка брони (5 сек)
                                      ↓
                            Статус изменен на Confirmed
                                      ↓
Клиент ← GET /api/bookings/{id} ← Получен актуальный статус
```
